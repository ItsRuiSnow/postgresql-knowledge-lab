# 第 01 课：关系型数据的基本结构

## 本课业务需求

存储文档和标签，并支持：

1. 一篇文档拥有多个标签。
2. 一个标签对应多篇文档。
3. 按标签查询文档。
4. 自动拒绝不存在的文档引用和重复关联。

## 为什么是三张表？

- `documents` 存放文档本身。
- `tags` 存放标签自身，`name` 不允许重复。
- `document_tags` 只保存两个主表之间的关系，由 `(document_id, tag_id)` 联合主键保证每对关系唯一。

文档和标签在业务上是多对多关系，通过关联表落实为两组一对多关系。

## 术语

- 表：一类数据的集合，例如 `documents`。
- 行：一条具体记录，例如编号 1 的文档。
- 列：记录的属性，例如 `title`。
- 主键（PRIMARY KEY）：唯一标识一行，且不可为 NULL。
- 外键（FOREIGN KEY）：限制关联编号必须指向有效的记录。
- JOIN：根据关联条件组合多个表的数据。
- CASCADE：在本课中，被引用的文档或标签删除时自动移除关联行。
